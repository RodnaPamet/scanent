# Engagement kit

Five pages for the people who arrange and run a scan with scanent. They are
written for readers who are not engineers.

| Page | Use it when |
|---|---|
| [Scoping checklist](scoping-checklist.md) | Before anything is installed: agree what is scanned, who grants access, where it runs and where the results go |
| [Access request templates](access-request-templates.md) | You need to ask a system's administrator for read-only access. One ready-to-send request per system |
| [Data handling](data-handling.md) | Someone asks what the scanner reads, writes, keeps and sends, who holds the signing key, and how to delete everything |
| [Run-book](run-book.md) | You are running the engagement: before, on the day, after |
| [Sample report](sample-report.md) | You want to show what the results look like, using made-up data |

A security reviewer should start at the [security pack](../security-pack/README.md).

## What to say about maturity

scanent has been tested and hardened in development. It has not yet been run
against a real organisation's systems, it has not had an external penetration
test, and no signed release has been published.
[Assurance status](../security-pack/assurance-status.md) lists what has and has
not been done. Say the same to the client.
