# scanent 0.18.1

A patch release of the image. The scanner reads and reports exactly what 0.18.0
did. The version names the image, so the version and its manifest hash moved.

## Why

From 2026-11-25, the Trivy gate on both images refused 0.18.0's runtime base,
`gcr.io/distroless/nodejs24-debian13:nonroot@sha256:39b04073…`. That base
carried `libzstd1 1.5.7+dfsg-1`, which is affected by CVE-2026-124851 (High).
Debian fixed it in `1.5.7+dfsg-1+deb13u1`.

The owner chose to wait for a patched distroless build rather than allowlist
the CVE, as was done for 0.17.0's `libc6`. That build was published on
2026-11-26. [#51](https://github.com/RodnaPamet/scanent/pull/51) moved both
Dockerfiles to it, at
`sha256:675c532423b908f9e56f9d60a4e62309b63cd2a3175acb90a46b96f7ee68e121`.

The published 0.18.0 image still carries the affected package. Anyone running
0.18.0 should move to 0.18.1.

## What changed

- **The runtime base**, as above, in the scanner's image. The prober's image
  (`deploy/probe.Dockerfile`) moved with it, and is still not published.
- **The version**, 0.18.1, in the scanner, the chart and the contract package.
  The contract package's code is the code of 0.18.0: it is republished under
  the version only because a release publishes it at the scanner's version.

Nothing the scanner reads, requests, writes or posts changed.

## The declared surface

Unchanged, apart from the version it names, and so its hash:
`sha256:cb8c4a8a289ea805eeb2952e9014971e5373ce7e85e896157f39ad4cef778e30`.
[Network and permissions](../network-and-permissions.md) lists it in full.

## What was run before the tag

- CI on Node 22 and Node 24, both image scans (Trivy and Grype) on the
  scanner's image and on the prober's, the cluster install on kind, and CodeQL,
  on #51 and on the commit that raises the version.
- The full test suite, locally, on the commit that raises the version.

## What has not been done

The same as for 0.18.0: read
[Assurance status](../security-pack/assurance-status.md) before relying on this
release. In short:

- **No probe report has been sent by a live run.**
- **No pilot at a client, no external penetration test, no 72-hour soak.**

## Known limits

The limits of 0.18.0 stand ([its notes](0.18.0.md#known-limits)).

## Upgrading

From 0.18.0, no configuration change is needed: pull 0.18.1. A consumer that
pinned the 0.18.0 manifest hash pins the new one. A consumer of the contract
package need not move: 0.18.1's modules are 0.18.0's.
