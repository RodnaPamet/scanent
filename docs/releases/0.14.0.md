# scanent 0.14.0

Its tag is made by the auto-release workflow on `main`'s head once CI has
passed there, not by a person.

## What changed

- **Results you can explore, and a PDF.** `summary.html` is still one file
  that reads in full with JavaScript off. With it on, it adds an interactive
  view: the estate's levels and findings at a glance, charts, the
  agent-by-criterion table with search, filters and a detail panel per agent
  and per cell, and the comparison with the previous run. `--out` also writes
  `report.pdf`, laid out inside the scanner with no browser.
- **One table model.** The table of agents and criteria is computed in one
  place, in the contract package (`harness-matrix-model`), and the page, the
  PDF, the CSV and `diff` all read it. An unregistered automated identity now
  reads "Held to no bar" on the page, as it already did in the CSV.
- **Payment capabilities (report contract `inflect-agent-harness/4`).** The
  `code` source reports an agent whose code calls an x402 payment client,
  with the call's location and never an amount, a wallet or a key. A
  registered agent that can pay raises `SPENDING_AGENT_UNDECLARED`; a
  standalone run reads no spending authority, so its finding says this run
  saw none. A card number anywhere in a report is refused like any other
  secret. Reports with `/2` and `/3` are still read.
- **A schedule longer than about 25 days** no longer runs scans back to back.
- **Memory.** A 5,000-agent run now peaks at about 1.1 GiB, so the Compose
  file and the chart limit the container to 1.5 GiB instead of 1 GiB.

## What was run before the tag

- CI on Node 22 and Node 24, the image scans (Trivy and Grype), the cluster
  install on kind, CodeQL and Scorecard, on the commit that was tagged.
- RUNS_PENDING
- SOAK_PENDING
- The page was opened in headless Chromium for the example estate and a
  synthetic 5,000-agent estate, light and dark, at desktop width and at
  390 pixels: no console error, no Content-Security-Policy violation, no
  network request. At 5,000 agents it loaded in 2.3 seconds and filtered in
  about 0.1 seconds.

## What has not been done

Read [Assurance status](../security-pack/assurance-status.md) before relying
on this release. In short:

- **No pilot at a client.** The one pilot was on the maker's own estate.
- **False positives and false negatives are not measured.**
- **No external penetration test and no independent code review.**
- **No 72-hour soak.** It is required before 1.0.
- **The payment reader has not read a real repository that pays.** It is
  tested against fixtures written from the payment libraries' own types.
- **The interactive page and the PDF have been checked on synthetic estates
  only.**

## Known limits

The limits of 0.13.2 stand ([its notes](0.13.2.md#known-limits)). Also:

- The PDF writes characters outside Latin-1 as `\u{…}` escapes rather than
  showing them.
- The PDF lists 500 agents and gives 100 a section of their own; it says where
  the rest are (the page and the CSV hold all of them).

## Upgrading

From 0.13.2: no configuration or inventory change. A consumer that verifies
reports must accept `inflect-agent-harness/4`; the contract package of this
version does. `--out` writes one more file, `report.pdf`.
